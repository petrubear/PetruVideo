# Implementation Plan: Project Creation, Media Import, and Basic Timeline with Trim

**Branch**: `001-project-media-timeline` | **Date**: 2026-10-30 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/001-project-media-timeline/spec.md`

## Summary

Build the foundation of PetruVideo: a project list, multi-select media import, and a single-video-lane plus audio-lane timeline with trim, split, duplicate, delete, detach audio, replace audio, and undo/redo, in compact, unfolded, and tabletop layouts that follow the designer's UI Reference canvas. Technical approach: a multi-module native Android app in Kotlin and Jetpack Compose; a pure-Kotlin editing engine (immutable timeline state, command-based edits with snapshot history) that is independent of Android; Media3 for preview playback and metadata; Room for non-destructive project storage with debounced autosave; Compose adaptive layouts plus Jetpack WindowManager for window size classes and fold posture; a design-token module generated by hand from the designer's palette and type.

## Technical Context

**Language/Version**: Kotlin (latest stable at scaffolding), JVM 17 toolchain

**Primary Dependencies**: Jetpack Compose + Material 3 (including adaptive/window-size-class libraries), Jetpack WindowManager (fold state and posture), Navigation Compose, Media3 (ExoPlayer; CompositionPlayer evaluated in research), Room, Hilt, Kotlin Coroutines/Flow, Coil (image loading for cached thumbnails). Exact versions pinned in the Gradle version catalog at scaffolding.

**Storage**: Room (SQLite) for projects, media references, and timelines; app-private files for thumbnail and waveform caches; original media is never copied or modified.

**Testing**: JUnit + Turbine + Kotest assertions on the JVM for the editing engine and view models; Compose UI tests and instrumented tests for flows; screenshot tests for design conformance on each screen and layout; manual device matrix for fold/unfold and tabletop.

**Target Platform**: Android, minSdk 26, targetSdk tracks latest stable; phones, tablets, and foldables (inner display flat and tabletop, cover screen).

**Project Type**: mobile-app (single Android application, multi-module Gradle build)

**Performance Goals**: 30 fps preview of 1080p footage on a mid-range device; UI interactions under 100 ms; 20-file import with all thumbnails visible in under 15 seconds; layout adaptation after fold/unfold under 1 second.

**Constraints**: offline-capable; no work lost beyond ~5 seconds after process death; originals byte-identical after editing; heavy work off the main thread and cancellable; no activity restart on fold, rotation, or resize.

**Scale/Scope**: 3 feature screens (Projects, Add media, Editor) in 3 layout families (compact, expanded, tabletop) plus the fold-aware projects/media two-pane; up to 100+ clips per project; projects up to 30 minutes of media.

### Source Code (repository root)

```text
app/                              # Application module: Activity, navigation graph, Hilt root, adaptive scaffold host
core/
├── model/                        # Pure Kotlin/JVM: Project, MediaItem, Timeline, clips, commands, history, format rules
├── data/                         # Room database, DAOs, repositories, autosave, media-reference fingerprints
├── media/                        # Media3 wrapper (preview engine), metadata probe, thumbnail + waveform generators, media source queries
└── designsystem/                 # Colors, type, shapes, spacing, icons, shared components from the designer's tokens
feature/
├── projects/                     # Projects screen, project list/detail two-pane, search, filters
├── importmedia/                  # Add media screen, selection state, permission flow
└── editor/                       # Editor screen: preview, transport, timeline, clip tool bars, inspector, tabletop layout
gradle/libs.versions.toml         # Version catalog
build-logic/                      # Convention plugins (Android library, Compose, Hilt, test config)

core/model/src/test/              # Engine unit tests (JVM)
core/data/src/androidTest/        # Room and migration tests
feature/*/src/test/               # View model tests
feature/*/src/androidTest/        # Compose UI and flow tests
app/src/androidTest/              # End-to-end flows and fold/resize tests
```

**Structure Decision**: Single Android app with a multi-module Gradle build, matching Principle VI. The editing engine lives in `core:model` with no Android dependencies so it can be tested on the JVM. Feature modules own their screens and view models and depend only on `core:*`. `core:designsystem` holds the designer's tokens so every screen draws from one source.
